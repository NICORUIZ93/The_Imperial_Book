# Plantilla de tema con subtemas atómicos

Usa esta plantilla para migrar un tema existente. Conserva todos sus conceptos y ejemplos válidos; divide el contenido cuando abarque varios conceptos nuevos. No pegues apéndices genéricos ni declares una práctica ejecutada si no se corrió.

```markdown
### Tema N: [resultado observable] · 25–35 min

**Proyecto del track:** [incremento que se conserva]
**Prerrequisitos:** [Track M<N> T<D> y herramienta necesaria]

#### Subtema N.1: [acción concreta] · 5–15 min

**1. Contexto**
[Problema real del proyecto y por qué importa. Define palabras técnicas la primera vez.]

**2. Hazlo tú**
[Indica el archivo exacto y su ruta. Incluye el código completo ejecutable o una ruta al laboratorio completo. La primera acción debe ocurrir en dos minutos.]

```bash
[comando exacto desde el directorio indicado]
```

**Salida esperada:** `[texto observable exacto o condición comprobable]`.

**Fallo deliberado:** [acción concreta]. **Error esperado:** `[mensaje o comportamiento]`. **Diagnóstico:** [por qué ocurrió y qué corregir].

**3. Entiende**
[Explicación sencilla del mecanismo, una decisión y un límite.]

**4. Cierra**
[Evidencia guardada y relación con el siguiente subtema.]

#### Subtema N.2: ...

[Repite los cuatro pasos. Cada tema tiene entre 3 y 6 subtemas.]

#### Subtema N.3: ...

### Hito del tema

- [ ] Ejecuté el ejemplo y observé la salida.
- [ ] Hice el fallo deliberado y expliqué el error.
- [ ] Guardé la evidencia indicada.
- [ ] Expliqué una decisión y un límite con mis palabras.
```

## Regla de calidad

El encabezado no acredita la práctica. Cada archivo, comando y salida debe existir y poder reproducirse. El checklist registra evidencias; no es una calificación ni una insignia. Revisa cobertura estructural, ejecución, navegador y calidad pedagógica humana por separado.
